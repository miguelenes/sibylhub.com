# Gateway guidance (SibylHub Gateway)

- `apps/gateway` is an independent Cargo workspace with its own committed `Cargo.lock` and a pinned Rust toolchain (`rust-toolchain.toml`, 1.93.1). Never merge it into the root Cargo workspace and never add its Rust dependency graph to pnpm; the package manifest is a thin bridge that invokes Cargo.
- Product identity: **SibylHub Gateway**. The code is derived from the AISIX AI Gateway by API7 (<https://github.com/api7/aisix>), Apache-2.0 — see `LICENSE` and `NOTICE`. Do not present it as the AISIX/API7 product, and do not rename provider or protocol identifiers (OpenAI, Anthropic, MCP, A2A, Bedrock, Vertex, Azure OpenAI, etcd, Redis).
- Compatibility aliases: legacy `AISIX_*` environment variables are read with a boot warning, and inbound `x-aisix-request-id` is still accepted. Emit only the new identifiers: `SIBYL_GATEWAY_*` env vars and `x-sibylhub-*` headers.
- Local development requires an untracked `config.local.yaml` (copy `config.example.yaml`). `pnpm dev` never starts the gateway; use `pnpm dev:gateway`.
- Deterministic checks run through the bridge: `pnpm --filter gateway build|lint|typecheck|format|test|test:cov`. The e2e harness (`test:e2e`) additionally requires etcd (and optionally Redis) plus its own pnpm 11 Node environment; MCP conformance (`test:mcp-conformance`) requires Node 22 or newer. Both are uncached, explicitly invoked tasks and are never part of root validation.
- Managed mode is a dormant upstream AISIX Cloud compatibility surface (default off). There is no SibylHub control plane; do not advertise one. The `/dp/*` wire contract and the `aisix-dp` User-Agent are preserved exactly while the surface exists.
- Keep provider keys, caller keys, and admin keys out of logs, tests, and tracked files. Passing local checks is local evidence only; it says nothing about deployment, image publication, or live provider traffic.
